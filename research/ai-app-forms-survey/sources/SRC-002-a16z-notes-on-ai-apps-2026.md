# Notes on AI Apps in 2026（全文提取）

## 核心论点

1. **Thinking tools vs Making tools**：现有知识工作工具全是"执行型"（IDE 写代码、Figma 做设计、表格建模型），"探索型"（帮人思考）的工具几乎没有，LLM 本身成了思考伙伴。编码 agent 能力增强后，难题从"怎么建"变为"建什么"（what do I build）。Cursor 是探索型走得最远的，Antigravity 是"agent first"产品设计。

2. **Software eats all the "service" functions**：每个团队每个任务（市场、法务、采购、财务）都应 software first。两类选择：领域专用产品（Harvey）或裸金属编码 agent（Codex、Claude Code）。"Every team should be a software team."

3. **Compounding AI apps**：进入推理模型第二年，AI-native apps 与模型继续分化：Apps = 前沿模型编排 + 领域专用 UI + 极其廉价的广泛功能面。"Narrow Startups"：极端专业化成为可能。错误假设是 apps 层会被模型层吞并（编码领域 2025 年新增超 10 亿美元收入）。

4. **Apps 层优势框架**（引用前文）：多模型、有封地数据资源（cornered data）、网络产品与生态、大量功能面。结合 Karpathy 的"thick AI apps"（多模型编排、autonomy slider、context engineering）。

5. **Humans discover "the rest" of AI**：命令行 UI 阻碍普通消费者使用 AI 最强能力。Wabi 将代码生成展示给消费者，ChatGPT/Grok 的 Images tab 做了同样的事，Apps Directory 和 Skills 将为 MCP 与 prompt 插件做同样的事。

## 对本文档的意义

- "Apps 与 Models 分化"是应用形态研究的关键判断：应用层的多样性会持续增长，值得建立分类学而非等待被吞并。
- Karpathy 的 thick app 概念（多模型编排、autonomy slider、context engineering）提供了一条形态维度：应用可以调节"自主度滑块"。
- "Exploration vs Execution"是一组新的工具分类轴。
