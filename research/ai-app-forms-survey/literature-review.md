# 文献综述：流程控制权的既有研究

> 项目：AI 应用形态调研（01.tools/pomasa/research/ai-app-forms-survey）
> 撰写：2026-09-19
> 目的：为「AI、人、确定性软件三者在信息系统中的分工」这一架构决策问题，梳理既有研究都做了什么、从什么角度切入、覆盖了什么、没覆盖什么，确认我们的生态位
> 方法：分轴检索（autonomy levels / human control / agent architecture / SE4AI / patterns / 中文语境），关键文献全文抓取落盘为 SRC，本综述只基于已落盘全文或确认过的摘要

## 一、六条既有工作线索

### 线索 1：自动化等级（人因工程，2000 年至今）

**代表**：Parasuraman, Sheridan & Wickens 2000（SRC-016）；Sheridan-Verplank 谱系；MATTERS 2025（SRC-011）。

**在做什么**：把"自动化程度"做成一条可从人全权到机器全权的等级轴，并分成四个阶段（信息获取、信息分析、决策选择、行动实施），每个阶段各有 10 级。核心发现：不同阶段不同等级的自动化对人的绩效影响不同，高等级自动化（尤其信息分析与决策选择）会导致 out-of-the-loop 效应，人脱离回路、情景意识下降、技能衰退。

**它的轴**：单一的人机二元轴（人 ↔ 机器）。机器是铁板一块的"自动化"，不分智能与代码。

**没覆盖**：AI 时代出现的新问题，语义开放任务、多智能体、契约与验证、概率智能的幻觉。机器是双元的（概率智能 + 确定性代码），人的位置也不止"在环/不在环"。

### 线索 2：智能体架构综述与模式目录（学术 SLR，2024 至今）

**代表**：JSS Agent design pattern catalogue（SRC-018，18 个模式）；Agentic AI 综述（SRC-008，六维分类）；多智能体编排综述（SRC-012）；Software Architecture Meets LLMs SLR（SRC-013）。

**在做什么**：对真实世界的智能体系统做系统文献综述，提取可复用的架构模式或分类体系。JSS 那篇与我们的工作最接近：18 个模式、context/forces/trade-offs、known uses、决策模型，格式与我们用的 PLoP/POMASA 模板同源（Meszaros & Doble 扩展模板）。

**它的轴**：智能体内部的组件与流程（目标创建、计划生成、反思、协作、监管、评估）。一切模式都发生在"智能体内部"，服务于"如何造一个更好的智能体"。

**没覆盖**：控制权放在系统层面考察。它把所有模式限定在智能体边界内，没有"确定性软件在系统里干什么"的位置，也没有把"人"当成一个有系统位置的机制（人只是其中的 human reflection 输入源之一）。

### 线索 3：有意义的人类控制（哲学 → 设计需求，2018 至今）

**代表**：Santoni de Sio & van den Hoven 2018（SRC-017）；后续 operationalisation 文献（Calvert 2025 等）。

**在做什么**：论证"人类必须最终保持控制并承担责任"，给出两个必要条件：tracking（系统要能回应设计者与部署者的道德理由及环境事实）和 tracing（系统结果总能追溯回设计链与运行链上的至少一个具体的人）。

**它的轴**：责任与合法性。从自主武器进入一般自主系统，是哲学与伦理层面的设计需求，不是工程模式。

**没覆盖**：怎么落地。tracking/tracing 如何变成可执行的结构（契约、门、血缘、验证）没有工程答案。这正是我们能接的桥。

### 线索 4：人在环/监督（软件工程实践与综述，2024 至今）

**代表**：Fowler/Kief Morris humans-and-agents（SRC-015）；HULA（human-in-the-loop LLM agents）；GAIE（graduated human oversight，三级监督）；HITL AI 系统综述（PMC，2026）。

**在做什么**：讨论 AI 辅助开发里人该站在哪。Kief Morris 给出最有分辨力的三个位置：人在环内（in the loop，逐行检查，人成为瓶颈）、人在环外（outside，vibe coding，质量失控）、人在环上（on the loop，不查产物而建设 harness：规格、质量检查、工作流指导），主张 harness engineering，并提出 agentic flywheel（人指示 agent 管理 harness 本身）。

**它的轴**：软件开发场景的单环模型（why loop / how loop），人在闭环里的位置。

**没覆盖**：它聚焦软件交付流程，argument 是"人应该管 harness 而不是管产物"。但没有把 harness 的内容系统化成模式语言，也没有展开确定性软件作为第三机制（harness 多半还是人写的规范，不是可执行系统）。GAIE 的三级监督（详见后文）是走向系统化的早期尝试。

### 线索 5：业界工程实践模式（Thoughtworks / Anthropic / Google Cloud / a16z）

**代表**：Fowler GenAI patterns（SRC-014）；Anthropic Building Effective Agents（SRC-001）；Google Cloud 智能体设计模式指南；a16z AI Apps in 2026（SRC-002）。

**在做什么**：把生产实践沉淀为模式：Fowler 从 Direct Prompting 出发的演进链（Evals → RAG → Guardrails → Fine Tuning）；Anthropic 的 workflows 与 agents 连续论与五种工作流；Google Cloud 的三步设计流程（定义需求 → 审查模式 → 选择模式），需求维度含任务特征、延迟、成本、**是否需要人工参与**。

**它的轴**：单一应用的工程技巧。做法都是"AI 内部怎么配"，人的参与只是需求清单里的一项（high-stakes 才需要人），没有形成系统的位置理论。

**没覆盖**：把"是否需要人工参与"当成一等公民。Google 的需求清单里它有名字，但只是一项 check，没有追问：人参与时以什么形态参与（对话？门？建模？），参与的成本与退化风险如何。

### 线索 6：中文语境与企业落地

**代表**：MaxKB（SRC-003，RAG → Workflow → Agent 的渐进路径）；AWS 中国企业级智能体系列；企业 AI 智能体基础设施的分层架构（田一晴 2026）；星球/知乎的 Agent 架构综述类文章。

**在做什么**：企业工程化落地的经验沉淀：执行隔离、可观测、治理、分层（模型层、智能体层、应用层）。MaxKB 的渐进路径很典型：先检索、再工作流、最后 agent，本质是在 D1 光谱上从静态端往动态端移动。

**没覆盖**：基本没有把"控制权"显式作为决策维度；企业叙述以"怎么把智能体做稳"为主，少有"该不该让智能体控制流程"的架构决策框架。这一条线的价值是案例素材（正是我们要"超越应用形态"的对象）。

## 二、对照：谁已经踩到了我们的问题边缘

最接近的有三处：

1. **JSS 模式目录（SRC-018）**：模式语言的形式最接近，但它定位在智能体内部部件层。我们的差异：系统级（人、AI、确定性代码三机制的分工与接口），不是智能体内部。
2. **MATTERS（SRC-011）**：直接提出"自主性是设计决策而非能力副产物"，五级自主性按用户角色划分（operator / collaborator / consultant / approver / observer）。它是最接近 D1 光谱的既有框架，且明确"user 可以是人或另一 AI"。但它的轴是"智能体单体的自主程度"，没有确定性软件的第三席，也没有门的工程化（门会疲劳、审产物非审过程）。
3. **Kief Morris 的 on-the-loop / harness engineering（SRC-015）**：明确提出"人建设与管理循环，而非检查产物"，与我们的「人即门」和「确定性机制工作清单」直接对话。但 harness 尚未系统化，且限于软件交付场景。

## 三、我们的生态位（差距分析）

综合六条线索，我们的问题"三者在完整信息系统中的分工与接口"没有被任何一条线正面覆盖：

| 线索 | 它的问题 | 我们的问题 | 差距 |
|---|---|---|---|
| 自动化等级 | 人机二元，等级轴 | 人 + 概率智能 + 确定性代码，三机制 | 第三机制缺席；智能与代码不分 |
| 智能体架构综述 | 智能体内部怎么设计 | 系统层面控制权放哪 | 粒度差异（内部 vs 系统） |
| 有意义的人类控制 | 责任如何成立（哲学） | 责任如何落成结构（工程） | 从设计需求到可执行模式的桥 |
| 人在环 | 开发场景里人站哪 | 任意系统中人的位置与接口 | 场景窄，未模式化 |
| 业界模式 | AI 单应用怎么配 | 架构决策框架 | 人只有 check 项，无位置理论 |
| 中文企业落地 | 智能体怎么落稳 | 决策该不该把控制权交给它 | 决策框架缺失，案例丰富 |

四条独立佐证说明我们处在一个真实、未被占据的位置：

1. **自主性等级谱系**（Sheridan 2000 → MATTERS 2025）证明"控制权可调、是设计决策"这条立场有二十年学术纵深，我们的 D1 光谱站在它肩上但加进了第三机制。
2. **JSS 模式目录**证明模式形式已被主流软件工程期刊接受，我们的贡献是把模式的粒度从智能体内部提升到系统分工。
3. **MHC 的 tracking/tracing** 为"人即门""血缘""契约"提供了哲学合法性：我们做的正是把这两个条件工程化。
4. **Fowler/Morris** 证明业界已在直觉层面到达"人管 harness 而非产物"，但我们把它写成可执行模式语言，其中 harness 明确由确定性软件承载（验证阶梯、门、契约），这是对业界直觉的系统化。

## 四、对论文叙事的启示

综述结果支持我们论文的两个立论：

1. **结构恒常，技术更替**。自动化等级（2000）、有意义的人类控制（2018）、人在环（2024）、智能体模式目录（2024）在不同时代反复追问同一个问题：控制权与责任如何分配。新变化不是问题变了，而是机器一侧裂成了概率智能与确定性代码两个机制，接口世界（MCP、A2A）正在重构。我们的坐标系统一了这几条线索的碎片：D1 对应自动化等级轴（加第三机制），D2 对应接口世界，D3 对应人在环与 MHC，D4 对应可审计性。

2. **模式语言是沟通层**。既有工作在哲学（MHC）、人因（LOA）、工程（JSS、Fowler、企业落地）、业界直觉（harness）四个层面各自碎片地触及这个问题。把它们翻译成同一套可执行模式语言，正好是 PLoP 该做的事，也是 POMASA（模式可执行）的用武之地。
